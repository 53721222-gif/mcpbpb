# bpbmaster

通过已有 MCP 实际游玩《背包乱斗》，优先提高每局完整存活 18 回合的概率。默认连续开休闲局；死亡或打完第 18 回合后重新开局，直到用户停止、达到用户指定的局数/时长上限，或遇到无法继续的接口问题。胜利十次必须选择进入生存模式，不能领奖结束。用户只要求创建、安装或审阅技能时，不开始游戏。

## 接口与开始条件

- 首次使用先读 [MCP 操作约定](references/mcp-contract.md)，核对当前客户端实际可调用的工具及参数；以下 `bpb_*` 是工具短名，按客户端的真实前缀调用。
- 先读 `bpb_get_state`，异常时用 `bpb_health` 诊断。游戏未启动或 MCP 不可用时说明具体缺口并暂停；不要改装游戏、改写存档或假装已执行。
- 使用当前配套 MCP 的 `wins` / `current_run_wins` 读取本局胜场，使用 `survival` 识别十胜提示和生存状态，通过 `bpb_enter_survival` 自动续局。若客户端未列出这些新增接口或运行中的服务仍缺少字段，报告版本不匹配并暂停，不能当作零胜或已进入生存。星位、耐力、配方和完整摆盘分别用 `bpb_get_star_slots`、`bpb_get_stamina`、`bpb_get_recipes`、`bpb_get_backpack` 读取；接口没有数据时明确说不确定，不要捏造。
- 所有操作串行执行，依据返回值和必要的新状态继续。金币、槽位、物品实例 ID、朝向和位置均以最新状态为准；刷新、合成、重开或重新连接后不能沿用旧 ID。

## 主循环

1. **进入休闲局。** 用户要求新开、重开或连续开休闲局时，在标题界面调用 `bpb_start_run {"mode":"unranked","force_new":true}`，确认进入 `shop` 且 `mode.name="Unranked"`；该调用会替换挂起的旧局。若用户只要求继续旧局，在标题使用 `bpb_continue` 并核对模式，不能强制删除旧局。职业和初始配置按用户指定；未指定就保留当前选择，根据其初始物品建立方向。若当前已有休闲局，继续当前回合；若当前是排位局，暂停并说明，不能按休闲流程代打排位。
2. **读取本回合。** 先检查 `survival.prompt_visible`，有提示时优先按后文进入生存；只在 `shop` 且有完整背包时读取商店、储物箱、背包、金币、回合、重试次数及本局胜场。接手时若仍在 `combat`，先等待结算，不能用空的背包摘要规划购买。
3. **购买循环。** 优先购买能实际部署且有助于存活、容量或构筑协同的商品，尽量把本轮金币投入背包、有效物品和合适的刷新。每次操作后重新评估资金、可用容量和合成；普通刷新按下一节的明确门槛持续进行，达到门槛后停止刷新，但仍可购买当前商店里买得起且值得的商品。
4. **严格完成三段编辑。** 购买完成后依次执行 `bpb_edit_items` → 摆物品 → `bpb_edit_bags` → 摆背包覆盖 → `bpb_edit_all` → 检查最终状态。中途补买或修复布局后仍要完成这一顺序。
5. **开战并等待。** 通过开战前检查后调用 `bpb_start_battle`，再调用 `bpb_wait_for_result {"timeout_seconds":90,"auto_skip":true}` 等待并推进普通结算；十胜提示由接口拦截，按后文自动进入生存。若需要观察普通结算可用 `auto_skip:false`，但该开关不负责生存选择。战斗中只等待或读 `bpb_get_phase`，不操作商店和背包。
6. **识别结算和下一步。** 每次等待或跳过返回后都核对 phase，优先处理 `survival.prompt_visible` 或 `survival_choice_required`，再区分下一回合商店与整局结束。不能因为到了第 18 回合商店就重开，必须完成该回合战斗及结算。确认死亡或第 18 回合已经结束后，在标题界面开新休闲局；界面尚未退出时先使用实际支持的结算操作。

## 购买、经济与合成

按当前能否存活和构筑收益决策，不固定照抄物品榜：

- **容量先行。** 计算已摆背包覆盖格的并集 `B`，以及计划上场的普通物品、技能和待合成材料的精确占格总数 `A`。买入前把候选物品占格也算入 `A`；储物箱中的背包没有实际部署前不算当前可用容量。已买待部署的背包可计入经过几何可行性检查的规划容量，避免为同一缺口重复买包，但最终以实际部署为准。目标是 `B` 略大于 `A`，为调整形状留少量余量；不能把 `width × height` 当成背包容量，也不能用矩形面积代替异形占格。
- **缺包优先买包。** `B` 不足、空隙碎片化、或大件无法完整装入单个背包时，优先购买能实际部署且形状合适的背包。容量和形状足够时优先买有效物品；不要囤积无处摆放的大件或为了余量过量买包。初期无合适背包时可保留核心商品，而非继续买进无处部署的物品。
- **前期买存钱罐。** 前几回合看到买得起、放得下的存钱罐时优先建立经济，但不能为额外的经济件牺牲维持生存所需的基础战力。收入数值、触发条件和收益时点只依据实际描述；存钱罐要进入最终有效背包，留在储物箱不当作已生效。中后期按剩余回合和占格机会成本决定是否保留，不继续无条件追经济。
- **优先完成关键合成。** 若当前商品能与已有物品合成构筑关键件，且配方已由可靠游戏信息确认，优先于普通小提升；同时检查合成前材料和合成后成品能否容纳。用 `bpb_get_recipes` 读取 `recipes/result/ingredients` 与 `as_ingredient`；没有配方数据时不凭名字臆造配方，只把确认的材料按实际占格相邻摆放，按真实回合推进检查是否合成。对于不得不相邻但不希望合成的物品何以使用融合锁定。
- **选择协同物品。** 围绕已有核心、职业和当前弱点采购，兼顾伤害、续航、防御和资源消耗。折扣、稀有度和单件看起来强都不能代替实际协同与占格效率。`shop.choose_one=true` 时是技能选择，按技能描述选一项，买后也要从储物箱摆入背包；选择后重新读普通商店。
- **钱不够就保留或换购。** 对下回合仍需要的商品调用 `bpb_reserve_item`，确认其可保留及保留成功；取消已过时的保留项。只有卖出最无用物品就能买到明确更有用的商品、且不会破坏当前战力或关键合成时才出售；不要卖核心、必要背包或仍有价值的材料。出售先看真实 `sell_price`，储物箱物品必须先合法放回背包再出售。
- **每轮尽量花完金币并持续刷新。** 先按容量、基础战力、协同和前期经济购买本轮值得且能实际部署的商品；没有值得购买的当前商品时刷新，继续寻找并购买。普通商店中，只要当前 `reroll_cost < 2`、金币足以支付这次刷新、且 `reserved_count < 2`，就可以继续刷新。每次刷新后重读状态；当金币不足以支付下一次刷新、刷新费升到 2 或更高，或已保留商品数达到 2 件时，停止刷新。达到这些条件后不再刷新，但仍可买当前商店中买得起且值得的商品并完成布置。只保留确实想留到下回合、当前又买不起的商品；目标是尽量把当轮资金用于背包、战力和刷新，不为凑零购买明显无用或无法部署的物品。`shop.choose_one=true` 的一次性技能选择阶段不是普通商店刷新流程。

## 摆放与覆盖

### 一、编辑物品

调用 `bpb_edit_items`，背包固定，物品可临时放包外，但仍不能越出棋盘或与其他物品占格重叠。

- 先规划整个棋盘的目标布局，优先关键合成对、核心输出和续航，再放辅助与经济件；提前考虑现有背包的形状，避免物品摆完后无包可覆盖。
- 按实际 `shape`、`cells` 摆放，紧凑填洞，减少狭长空隙。`bpb_place_item` 使用游戏原生 `pickup(当前位置) → 设目标包围盒中心 → drop()`，成功返回的 `cells` 精确等于目标格；失败返回 `placement_rejected`。需要改变朝向时用 `bpb_rotate_item`；目标格必须全在包内且不重叠，否则返回 `cannot_rotate_in_place`。
- **融合锁定**：用 `bpb_set_fusion_lock`（`item_id` + `locked=true/false`）阻止或恢复物品的自动融合；`state.backpack.items[].fusion_locked` / `storage[].fusion_locked` 是当前状态。需要保留材料、避免误合成时锁定；要合成时先解除，否则配料不会被消耗。锁定不阻止移动/出售/旋转，背包本体不可锁定。
- **宝石镶嵌**：`state` 的 `item.sockets` 给出每个镶嵌位的 `index/occupied/gem_id`；用 `bpb_socket_gem`（`host_id` + `gem_id` + `socket_index`）把煤炭、红宝石碎片等 `is_gem=true` 的宝石镶到武器/防具空位；用 `bpb_unsocket_gem` 取下。已占用位先取下再换，不能假设 hotswap；宝石可来自背包或储物箱。
- 尽量让星位命中符合描述的物品，优先高收益协同，再争取更多有效触发。用 `bpb_get_star_slots` 读取 `affected_cells`（方向 key）与 `current_affected_items`；星位方向随朝向核对；“普通相邻”不等于“命中星位”。无法读取对应物品时明确保留不确定性，不宣称已验证星位全部触发。
- 需要合成的两件材料让实际占格边缘相邻；若真实配方有特殊位置/方向要求，按该要求摆放。不只比较左上角坐标，也不把对角接触默认算作有效相邻。

### 二、编辑背包

调用 `bpb_edit_bags`，物品绝对坐标固定，再用 `bpb_place_bag` 移动空背包。新买的背包也要从储物箱部署；空背包可用 `bpb_rotate_bag` 原子旋转；非空背包返回 `bag_not_empty`。

- 优先完整覆盖关键物品和关键合成材料，再尽可能覆盖辅助与经济件；兼顾背包本身的效果描述。
- **游戏允许一件物品同时覆盖多个背包，不要求属于单一背包。** 只要每格都是合法棋盘格、物品之间不重叠即可；不要因为 `in_one_bag=false` 把物品移走。最终检查 `floating_count == 0` 和关键物品仍在背包中。
- 背包之间不能重叠且不能越界；移动背包不会把物品一起搬走。需要交换位置时先规划空位和移动顺序，避免来回碰撞。

### 三、编辑全部与开战检查

调用 `bpb_edit_all` 后重新读完整状态。它只规范化位置/朝向，不会因跨包把物品移入储物箱；检查实际已部署清单。

开战前确认：`state=shop`、`edit_mode.name=all`、`can_start_battle=true`；关键输出、续航、技能、计划生效的存钱罐和合成材料均已部署；每件物品实际 `cells` 在棋盘内且彼此不重叠、`floating_count=0`；**允许跨包，不需要 `in_one_bag=true`**。储物箱允许保留明确暂不上场的次要物品，不要求清空。

若关键物品掉进储物箱，重新走“编辑物品 → 编辑背包 → 编辑全部”修复；确实装不下时重新评估次要物品、背包购买或换购。`can_start_battle=true` 只是按钮可点，不证明布局和战力合理。

## 十胜、生存与结算

- **以接口胜场为准。** `wins` 和 `current_run_wins` 都是本局胜场，`total_wins` 是累计胜场，不能用后者触发十胜流程。接手中途局也直接读取本局胜场，不再自行从零累加或通过回合、`tries`、`last_result` 推算。`last_result` 仅用于结果记录，不能当作当前战斗实时胜负。
- **十次胜利后必须自动进入生存模式。** 每次状态或结算返回后，优先检查 `survival.can_start`；十胜时它可能比 `prompt_visible` 早约 1 秒变为 `true`。当 `can_start=true` 时直接调用 `bpb_enter_survival {}`（会主动打开延迟中的提示，不会先结算奖杯）；也可使用等价的 `bpb_choose_survival {"choice":"survival"}`，两者选一个，不连续重复选择。无需让用户再次确认。
- **把选择请求当作流程分支。** `bpb_wait_for_result` / `bpb_skip_result` 返回 `error="survival_choice_required"`，或 `error="skip_failed"` 的 `detail.error` 为该值时，即使 `ok=false` / `isError=true` 也应进入上述生存选择流程，而非报告工具故障、等待人工处理或重开。先用返回的状态或 `bpb_get_phase` 确认提示；不能连续调用跳过来绕过选择。
- **选择后验证继续本局。** `bpb_enter_survival` 成功返回的状态在 `phase` 中；随后重新读取 `bpb_get_phase`，确认 `survival.prompt_visible=false` 且 `survival.survival_mode=true`。转场未完成时有限等待；回到 `shop` 后再读完整状态继续购买。若仍在 `combat`，按实际 phase 等待或处理普通结算，不重复开战或新开一局。已在生存模式且没有提示时不要再次调用进入生存。
- `wins` 达到十次但 `survival.can_start` 仍为假时等待并重读，不要先 `bpb_skip_result`；`can_start=true` 后立即进入，不要求 `prompt_visible` 已为真。`survival_mode` 才是已经进入生存的确认字段，不能仅凭 `wins`、`total_wins` 或 `survival.was_max_wins` 推断。进入后 `just_started=true` 时等切回 shop，不要 skip；出现 `survival_prompt_not_visible` 时先读 phase，若 `can_start=true` 可重试 `bpb_enter_survival`；持续无法进入时保留当前局并报告具体错误。
- 本技能目标下禁止调用 `bpb_stop_here` 或 `bpb_choose_survival {"choice":"stop"}`。`survival.can_stop_here=true` 只表示该按钮可用，不是应该结束本局。`bpb_start_run` 的 `unranked/ranked` 仍只用于新局，不接受 `mode=survival`；不能用强制重开绕过十胜续局。
- 战斗等待超时或返回成功但仍处于 `combat` 时，先读 `bpb_get_phase`，区分战斗未完、普通结算、商店转场与生存提示；不要只凭 `result="skipped"` 判断已经回到商店。仅在本局未到十胜、没有生存提示且 `can_skip_result=true` 时手动 `bpb_skip_result`；十胜前后都不要 skip，超时不等于死亡。
- `tries` 是剩余重试次数，`hp` 是角色战斗生命；不能因为一场战斗生命变为零就认定整局死亡。以真实终局/返回标题/确认重试耗尽判断本局结束。

## 运行记录与停止

每回合维护简短记录：局号、回合、重试次数、接口返回的本局胜场与生存状态、当前编辑/战斗阶段、核心与合成计划、保留商品，以及有意留在储物箱的物品。新局清空旧局记录和所有实例 ID，再读取新局胜场；累计 `total_wins` 不应人为清零。上下文恢复时先读实时状态再用旧计划。

对失败操作先读返回错误，再用新状态纠正模式、ID、坐标或资金；同一原因连续失败三次且没有新的恢复动作时暂停，说明卡点。游戏断线、关键生存选择不可操作或用户要求停止时也暂停；暂停前若仍在可操作商店且有未完成布局，尽量完成最终化和关键物品核对。不要通过无休止刷新、重开或重复失败请求维持循环。

每回合用一句话概括关键购买/合成、布局状态和战斗结果；整局结束报告是否完成第 18 回合、终止原因和下一局的针对性调整。没有实战验证就不声称保证十八回合。
